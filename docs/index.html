DynamicResume keeps every role, bullet and skill in one master file. For each listing it picks the bullets that match, lays them out with Typst, and tells you exactly how full the page is. It runs on your machine, and your data never leaves it.

      From listing to sent, in one local app

      Claude drafts it. You decide.

      Paste a job listing and choose Create and draft with Claude. Claude Code runs headlessly with read-only tools, reads your master and the listing, then picks and orders bullets, writes a headline and a cover letter, and breaks the listing into requirements.

      It also says what your master can't back up. Those gaps get a topic, and the Gaps view ranks them across every application, so you know which bullet to write next.

      Edit against the listing, with a live page

      Every requirement is a chip that turns green when a selected bullet backs it up. Tick bullets on and off, drag them into order, or reword one for this job only. The preview rebuilds as you go.

      The fill meter shows how much room is left. Each bullet shows its line count, and a bullet whose last line holds only a word or two gets flagged, because trimming it saves a whole line. Nothing ever shrinks the font.

      Track it after you hit send

      Mark submitted freezes the exact PDFs you sent, along with the files that made them, so when a studio calls back you can open the resume they actually have.

      Then drag the card along the board as you hear back: screen, interview rounds with format and interviewers, offer, rejected or ghosted. Timeline and Stats show reply rates, days to a first reply, and what's coming up.

      Impact check
      Every master save rebuilds each application in the background and tells you which ones changed length or went past one page.
      Short versions and variants
      A bullet can carry a tighter wording, or an alternate version for listings that ask for something specific. The build refuses a bullet and its variant together.
      ATS-friendly output
      One column of real text and standard headings, with the company repeated on every role so autofill never reads a team name as your employer.
      Matching cover letters
      Written in Markdown, laid out with the resume's header, colors and margins, and drawing on your notes about the studio.
      Writing lint
      Builds flag em dashes and filler such as "leverage", "spearhead" and "passionate about".
      Nothing gets lost
      Comments in your YAML survive every save, each master save keeps the previous version, and snapshots zip everything before a redraft or delete.

      Under the hood

      About 6,000 lines of Python, Typst and plain JavaScript. No framework, no bundler, no database: YAML files you can read and edit, a standard-library server, and a template that measures its own layout.

      A template that measures itself

      Typst lays out the page, and while it does, each bullet records how many lines it took and how full its last line is. build.py queries those labels instead of guessing from character counts, so "about 16 lines free" means 16 lines.

      // templates/timeline.typ
let n = lines(b.text)
...
[#metadata((id: b.id, lines: n,
  last: measure(tail).width / width)) <bullet-fit>]

      An agent with read-only hands

      Drafts run Claude Code headlessly in the data folder, so the project's own rules apply. It can read, glob and grep, and nothing else. It answers with one JSON object, and every bullet id in it is checked against the master before a file is written.

      # studio/draft.py
READ_ONLY = ["Read", "Glob", "Grep"]
cmd = [exe, "-p", "--output-format", "stream-json",
       "--allowedTools", *READ_ONLY,
       "--disallowedTools", *DENY]

      Local by construction

      The editor is a standard-library ThreadingHTTPServer bound to 127.0.0.1, serving one page of plain JavaScript with no build step. It rejects other Host headers to block DNS rebinding, and writes need a custom header that other sites can't send.

      # studio/server.py
if host not in ("127.0.0.1", "localhost"):
    return self.send_json({"error": "bad host"}, 403)
if method != "GET" and self.headers.get("X-Studio") != "1":
    return self.send_json(..., 403)

      Your files stay yours

      The app and the command line edit the same YAML. Saves go through ruamel's round-trip mode, so your comments and layout survive, and the app notices edits made in a text editor within a couple of seconds. Git worktrees all share one copy of the data.

      # tailor.yaml: a few lines per job
headline: Senior Gameplay Designer | Combat, Balancing
positions:
  dd-designer:
    bullets: [dd-bosses, dd-enemies, dd-abilities]
short: [rr-lead]

      CI that guards a public repo

      The tool runs on personal data in a public repository. A privacy job scans every tracked file, and the text inside the demo PDFs, for real emails, phone numbers, home-folder paths, and a secret list of names that must never be committed.

      Syntax and lint        ruff, node --check
Privacy guard          tracked files + demo PDF text
Unit tests             pytest, demo data only
Demo build (Windows)   one page, ATS text, fresh PDFs

      Tested the way an ATS reads

      Applicant tracking systems read text, not layout. The Windows CI job builds the demo with real Typst, then reads the PDFs back with pypdf to check headings, section order, contact details, the company on every role, and that the committed PDFs match a fresh build.

      # tests/test_ats.py
def pdf_text(path):
    from pypdf import PdfReader
    return "\n".join(page.extract_text() or ""
                     for page in PdfReader(path).pages)

      Try it on the demo data

      You need Python 3 and the Typst CLI. The demo opens the editor on a fictional designer with four applications at different stages. Drafting with Claude needs Claude Code installed and signed in; without it, you pick the bullets yourself.
